# Декларация Максима — исходники и сборка для GitHub Pages

## Публикация через GitHub Pages

Опубликованная статическая версия: https://neonoise.github.io/declaration-dashboard/

GitHub Pages настроен на публикацию из ветки `main`, папки `/docs`, с обязательным HTTPS. Готовая автономная версия находится в `docs/index.html`.

После изменений исходников перед отправкой в репозиторий пересоберите страницу:

```sh
python build_local.py docs/index.html
```

Затем включите обновлённый `docs/index.html` в коммит и отправьте его в `main`.

**Это статическая версия.** Чек-листы, проценты, диаграммы и экспорт работают в браузере. Отметки каждого посетителя хранятся только в его браузере. Общего серверного прогресса, пользовательских аккаунтов, приглашений и совместных комментариев на GitHub Pages нет. Эти возможности остаются в серверных исходниках ниже и требуют отдельного серверного размещения.

Сборка содержит только исходные данные декларации без внесённого прогресса, базы пользователей и секретов. На GitHub Pages доступна эта статическая редакция; серверная версия развёртывается отдельно.

# Декларация Максима · интерактивный дашборд

**Статус поставки:** статическая редакция доступна на GitHub Pages: https://neonoise.github.io/declaration-dashboard/. Автономный HTML и серверная версия имеют одинаковый интерфейс, но разные возможности совместной работы.

## Что входит

`declaration-local.html` — автономная страница для личного использования. Откройте её в браузере. На странице прямо обозначено отсутствие общей синхронизации. Отметки сохраняются через локальное хранилище браузера; при недоступном хранилище выводится ошибка, а не сообщение об успешном сохранении. Для переноса отметок используйте меню «Действия → Скачать резервную копию / Импортировать отметки». Копия включает личные оценки баланса. Для друзей используйте текстовый отчёт.

Серверный проект — `app.py`, `storage.py`, `model.py`, `declaration.json`, каталог `public`. Состояние, пользователи, приглашения, комментарии и история хранятся в SQLite в каталоге `DATA_DIR`. **Для публикации нужен сервер с постоянным диском и HTTPS. Простое размещение HTML на статическом хостинге не включает совместную работу.**

`preview/` — внешний вид начального экрана без выдуманного прогресса. `QA.md` — объём и ограничения проведённых проверок.

## Содержание декларации

Основание — подписанный документ от 15.08.2026. Дедлайн — 31.10.2026, календарь Минска. Сохранены шесть обязательств в подписанном порядке: оргструктура ФТФ; делегирование этапа; передача технического опыта; колесо жизненного баланса; разговор с женой; отдельная встреча с родителями. Цена слова — 1 000 у. е. Награда — «Крутой исинский чайник». Изображение и подпись не включены. Приложение не выполняет платежей.

Рабочие чек-листы содержат 24 шага. Это декомпозиция подписанного текста, а не дополнительные обязательства. Промежуточные даты не придуманы и изначально пустые. Фактический прогресс изначально не задан.

## Как пользоваться

На экране «Обзор» откройте карточку. Во вкладке «Шаги» отмечайте действия и задавайте необязательные сроки. Во вкладке «Результат» подтверждайте исходные критерии. Для бизнесовых задач можно добавить общедоступное для группы пояснение и HTTPS-ссылку. Для личных задач доступны только статусы, плановые даты шагов и момент подтверждения; содержание семейных разговоров не собирается.

Во вкладке «Шаги» обязательства №4 доступно интерактивное колесо баланса. Оценки 0–10 и личная заметка закрыты для других участников на уровне серверного ответа. Сохранение оценок не проставляет галочки автоматически. Это личная самооценка, а не медицинская диагностика.

«Карта задач» раскрывает цель, бизнесовый и личный контуры и шесть обязательств. Нажатие на узел открывает шаги. «Динамика» показывает реальные сохранённые изменения; начальные значения и прошлые достижения не генерируются. «Декларация» содержит текст подписанного документа и команду печати. «Обсуждение» — общая лента группы.

### Методика процентов

Общий процент действий — среднее шести долей выполненных шагов. Каждое обязательство имеет вес 1/6, независимо от длины чек-листа. Выполнение одного полного чек-листа даёт примерно 16,7%. Отдельный счётчик «Принято X / 6» зависит только от исходных критериев. Подготовительные действия и приёмка результата не смешиваются. Подтверждение владельцем не означает независимой проверки группой.

## Сервер: локальный запуск

Нужны Python 3.11+ и зависимости из `requirements.txt`. Проверки выполнены на Python 3.13.5.

```sh
python -m venv .venv
# Linux / macOS:
. .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run_local.py
```

Откройте `http://127.0.0.1:8000`. В консоли первого запуска будет уникальный код первичной настройки. Введите его в форме и создайте учётную запись владельца. Не отправляйте код настройки участникам. По умолчанию база сохраняется в каталоге `data/` рядом с приложением. Повторная регистрация владельца блокируется.

`run_local.py` слушает только локальный интерфейс. Этот запуск не создаёт интернет-ссылку.

## Сервер: публикация

Выберите среду, поддерживающую Python-процесс и постоянный диск. Экземпляр приложения должен использовать одну и ту же базу в `DATA_DIR`. Несколько независимых копий диска не дают общей базы. Для небольшой мастермайнд-группы предусмотрен один экземпляр приложения. Не используйте временную файловую систему как единственное хранилище.

При публикации задайте `COOKIE_SECURE=1`, `PUBLIC_URL` равным фактическому HTTPS-origin без пути и `DATA_DIR` на постоянном диске. Внешний HTTPS-прокси передаёт запросы процессу приложения. Не публикуйте SQLite-файл, логи с кодом первичной настройки и резервные копии в открытом каталоге.

В комплекте есть Dockerfile и compose.yaml для сервера, где HTTPS-прокси уже настроен:

```sh
cp .env.example .env
# Укажите в .env свой реальный HTTPS-origin.
docker compose up -d --build
docker compose logs dashboard
```

Compose открывает приложение только на `127.0.0.1:8000` хоста. Настройка домена и HTTPS-прокси выполняется отдельно. Том `declaration-data` хранит базу между перезапусками. Не удаляйте его при обновлении. Docker-сборка в этой среде не выполнялась; локальный запуск API и проверки выполнены отдельно.

Документация используемого сервера: https://www.uvicorn.org/settings/
Концепции публикации FastAPI: https://fastapi.tiangolo.com/deployment/concepts/

## Права и приглашения

Владелец создаёт приглашение через «Поделиться». Ссылка одноразовая и действует 7 дней. Имя при выдаче служит напоминанием, кому адресована ссылка; её фактического получателя следует проверить лично. Любой человек, получивший ещё не использованную ссылку, может принять её. Участник выбирает собственные имя, логин и пароль. Это не автоматическая верификация личности по электронной почте.

Участник видит текущий прогресс и публикует комментарии, но не может изменить задачи, критерии, сроки, подтверждения и роли. Сервер проверяет права независимо от интерфейса. При отзыве доступа активные сессии участника завершаются. Старые комментарии остаются в истории. Без входа API декларации не открывается.

Обновления запрашиваются каждые 12 секунд при открытой активной вкладке. Это периодическая синхронизация, а не обещание мгновенной доставки. Конфликт одновременного редактирования владельцем с двух устройств возвращает ошибку версии: приложение загружает актуальные данные и предлагает повторить действие. Отсутствие связи отображается явно.

## Резервные копии

Экспорт из интерфейса сохраняет отметки, сроки, материалы, личные оценки и загруженную историю/комментарии. Импорт переносит **только состояние** (отметки, сроки, материалы, личные оценки); комментарии и история из чужого файла не подмешиваются. Новое состояние записывается как текущее действие, а не как доказанная работа в прошлом.

API выдаёт последние 400 изменений и 500 комментариев; сама база не удаляет старые записи. Для полного резервирования серверных данных, включая учётные записи и полную историю, администратору следует делать резервную копию SQLite средствами SQLite и хранить её приватно. Пользовательский JSON-экспорт не является резервной копией учётных записей. Самостоятельного восстановления пароля по email в этой версии нет; для восстановления доступа нужен администратор сервера.

## Проверки

```sh
pip install -r requirements-test.txt
python -m pytest tests/test_app.py -q
node --test tests/core.test.js
```

Для браузерного smoke-теста с реальной навигацией запустите API и отдельно локальную HTML-страницу через HTTP, затем выполните `tests/browser_smoke.py` с `TEST_BASE_URL` и `TEST_LOCAL_URL`. Этот сценарий подготовлен, но в текущей среде не завершён из-за политики запрета навигации Chromium.

`tests/render_harness.py` проверяет интерфейс на about:blank с явно подставленными тестовыми адаптерами хранилища и in-process API. Он не изменяет политики браузера и не является проверкой публичного развёртывания. Результаты и ограничения — в `QA.md`.
